# Quality and delivery

Inspect actual Figma frames and prototype presentation, not just tool success messages. Capture each screen at its intended viewport plus close-ups where scaled images obscure details. Check these dimensions against the brief:

- Product: primary action, information hierarchy, truthful copy and complete requested screen/state inventory.
- System: correct semantic token use, reusable instances, coherent component states, verified font, meaningful names, resize behavior.
- Visual: no overlap/clipped text, intentional whitespace, real asset fills, consistent crops, readable detail and useful contrast.
- Interaction: primary path, cancel/back/return, validation and recovery, actual prototype starting points and linked destinations.
- Platform: keyboard/focus expectations, touch/input affordances, safe areas/window chrome and device/window variations from the playbook.
- Accessibility: contrast measurements where available, visible focus, non-color status cues, text resizing considerations and adequate target sizes using current target-platform guidance. A Figma inspection alone does not certify runtime WCAG conformance.

Record each issue with severity, frame/node reference, observed symptom and correction. An overall aesthetic score is supplementary; critical functional or missing-screen issues cannot average away. One batched review, one correction batch, one confirming review is the normal finish. A second correction pass can resolve a remaining known defect; if still failing, return the concrete blocker rather than polish indefinitely.

Handoff must contain actual file/frame/prototype links, ordered page map, requested-versus-delivered inventory, components/tokens, assets and provenance, verified interactions, unsupported simulations and remaining issues. Include screenshot evidence for canvas changes. Clarify which artifacts are designs, generated media, prototype interactions or implementation notes. Never label a Figma design a deployed landing page or compiled mobile/desktop app.

The local helper's evidence record is an agent attestation. It requires fields and dependency order, but cannot authenticate external node IDs, URLs, screenshots or tool execution. Record only work actually observed. Browser-only evidence may use exact frame names and screenshot refs if IDs are unavailable.
